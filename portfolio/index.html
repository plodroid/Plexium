How a project works

Simple process. No weird agency maze.

You should know what happens before the first line of code gets written.

  1. 1

    Pick the rough level

    Use the pricing above to work out whether the project is simple, basic, advanced or a full build.

  2. 2

    Agree on the scope

    Pages, features, visual direction and anything the project absolutely has to do get written down first.

  3. 3

    I build and test it

    The project gets made around the agreed scope, then checked across common screen sizes and input methods.

  4. 4

    You review it

    A normal polish pass is part of the process. Big new features added after the scope are treated as extra work, not hidden inside the original quote.

  5. 5

    Launch + handoff

    The finished project can be prepared for deployment and the source can be handed over with the important files kept understandable.

Before you ask

The stuff clients normally want to know.

If you’re checking this page in person, this section should answer most of the obvious questions before we even start talking.

Will the site work properly on phones?

Yes. Responsive behavior is part of the build, not a paid add-on. Navigation, text size, spacing and touch targets are designed for smaller screens too.

Do I need to already own a domain?

No. A project can be built and previewed first. If you want a custom domain later, I can help connect it. The cost of a paid domain or hosting provider is separate from the development price.

Can you redesign something I already have?

Yep. If the content or backend already works, the job can focus on structure, visuals, mobile behavior and interaction instead of rebuilding everything for no reason.

How long does a project take?

It depends on scope. A focused site is obviously faster than a full app with stored data and multiple workflows. The schedule is agreed before the build starts so there isn’t a random deadline invented halfway through.

What do I need to provide?

If you have a logo, photos, menu, service list, prices or existing text, send them. If not, the project can start with a clear structure and placeholders while the final content is prepared.

Do I get the source code?

For normal custom projects, yes — the source can be handed over. If a project ever uses a third-party licensed asset or service, that part follows its own license instead of pretending it belongs to us.

What happens if I ask for extra features later?

Small polish is one thing. A whole new feature is another. Anything that changes the agreed scope gets priced clearly before it’s added, so neither side has to guess.
